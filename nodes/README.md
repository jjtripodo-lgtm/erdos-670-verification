# Exact transformed-node preflight

These are code-only mechanical translations of the [frozen fixed-dimension
formalization](https://github.com/jjtripodo-lgtm/erdos-670-fixed-dimension/tree/1e73a12ff1076dd11affadbf619ddbbef587133e),
using the real declaration/source-position facts from successful extraction
[run 38350587663](https://github.com/jjtripodo-lgtm/erdos-670-verification/actions/runs/38350587663).
The source theorem and mathematical claims are unchanged.

The compact decomposition has 28 definition bundles and 10 theorem/solution
pairs. The main theorem plus the nine proofs longer than 40 lines become nodes;
medium supporting proofs remain inline. All 442 reachable source declarations
are accounted for. The official importer [allows tuning these default
thresholds](https://github.com/prove2me/prove2me_workspace/blob/78989800ba0b3149ee34205257025bd0f617e8ef/references/upload_full_project.md#phase-2--plan-the-node-set).
No proof text is regenerated by a language model: commands are retained or
subtracted using Lean-emitted byte ranges. One private proof needed inside a
definition bundle is made public using its exact token range. The 10 node names
already satisfy the platform's conservative ASCII naming requirement.

`fixtures/` stores 104 exact candidate files. Live Lean files have a `.txt`
suffix here so this independent preflight does not introduce additional live
Lean modules into the Palomar repository scan. `FIXTURE_MAP.json` records the
exact destination paths, sizes and hashes. `GENERATION_RECEIPT.json` is a dated
generation receipt, not a compilation result. The proof stubs intentionally
contain `sorry`; they are dependency interfaces, not proofs.

The manual `Pinned Prove2Me transformed-node preflight` workflow materializes
these bytes on a separate standard Ubuntu VM and checks:

1. All 28 Definitions, 10 Theorems and 10 Solutions modules compile on Lean
   4.33.1 with the exact nine dependency commits used for successful extraction
2. The staged theorem is byte-for-byte its saved `preamble + formal_statement`;
   each staged solution is byte-for-byte the saved solution payload
3. Every staged theorem type exactly matches its original detailed type dump.
   Solutions use the same strict text comparison first. Only after a statement
   has passed may a solution-only mismatch use a synchronous Lean-kernel check:
   the already-compiled solution constant must have that exact statement type.
   The bridge requires identical universe-parameter lists and trust level zero,
   rejects altered-type/index negative controls, and rechecks both detailed type
   strings against the isolated probes. No proof-name normalization is performed
4. All 92 definition-material/proof declarations use only `propext`,
   `Classical.choice` and `Quot.sound`; no definition imports a theorem stub
5. Solutions never import their own target. A solution can depend on `sorryAx`
   only through its explicitly listed reduction stubs; leaf solutions cannot
   have it. This is a preflight boundary, not platform proof acceptance

The separate kernel probe may import the statement stub alongside an already
compiled solution for type comparison only. Its checked witness is the solution
constant, never the statement stub, and the solution's axiom audit still comes
from its original isolated probe. The kernel API is called synchronously with
checking enabled; no elaborator-unification result substitutes for kernel
acceptance. Reports distinguish exact-text matches from kernel-checked matches
and retain separate hashes for the unmodified original and staged type strings.

The runner needs 16 GiB initially. The guarded build/cache/type-check commands
require 8 GiB free disk and 1.5 GiB available RAM, with a 20-minute limit per
command and 180 minutes overall. No unrelated files are removed. There are no
platform API calls, secrets, private fetches, extra Actions, uploaded artifacts,
or reusable GitHub cache writes. Only ordinary public logs and summaries are
retained. Theorem/definition metadata, authenticated environment/collision
checks, and any later platform submission remain separate gates.
